Unit 1 — The NetLogo world

An agent-based model represents a system through individual entities (agents), their attributes, the environment they occupy and the rules governing their interactions.

1. Four building blocks

  • turtles — mobile agents that can move around the world.
  • patches — the fixed square cells that make up the world.
  • links — connections between turtles.
  • observer — the global perspective that controls the model.

2. A first small model

This example creates 20 turtles at random positions. Each turtle is coloured blue.

to setup
  clear-all
  create-turtles 20 [
    set color blue
    setxy random-xcor random-ycor
  ]
  reset-ticks
end

3. What does the code do?

  • clear-all clears the previous model state.
  • create-turtles 20 creates 20 turtle agents.
  • set color blue sets each turtle's colour.
  • setxy places each turtle at a random x-y position.
  • reset-ticks resets the model's time counter.
Try it in the NetLogo desktop application: create a new model, paste the code, add a button linked to setup, and run it. This academy does not embed or execute NetLogo itself.

Unit 2 — Turtles, patches and links

In Unit 1, you created turtles. Now we examine the three agent types that make up the visible structure of many NetLogo models: mobile turtles, fixed patches and links connecting turtles.

Learning objectives

  • Distinguish turtles, patches and links by their roles.
  • Use ask to give instructions to the appropriate agents.
  • Create an undirected link between turtles.
  • Read a small spatial network model and explain its structure.

1. Turtles: mobile agents

Turtles can move around the two-dimensional world. Each turtle has a position (xcor and ycor), a heading and built-in characteristics such as color, size and shape. In a household model, a turtle could represent a household; in a diffusion model, it could represent a person or organisation.

create-turtles 10 [
  setxy random-xcor random-ycor
  set color blue
]

ask turtles [
  right random 360
  forward 0.5
]

The first block creates ten turtles and places them randomly. The second block asks every turtle to turn and move forward. The commands inside ask turtles run in turtle context, so turtle commands such as forward are valid there.

2. Patches: the fixed environment

The world is divided into square patches. Patches do not move. They can represent land cover, habitat, neighbourhood conditions, pollution levels or the location of infrastructure. Each patch has coordinates pxcor and pycor and a colour pcolor.

ask patches [
  if pxcor > 0 [ set pcolor green ]
  if pxcor <= 0 [ set pcolor brown ]
]

This colours the right half of the world green and the left half brown. Notice the different context: pcolor and pxcor belong to patches, so the instructions are given using ask patches.

3. Links: connections between turtles

A link connects two distinct turtles. It has no patch location of its own; it is drawn between its two turtle endpoints. An undirected link represents a mutual relationship, while a directed link represents a one-way relationship. For example, an undirected link may represent a mutual peer relationship; a directed link may represent information flowing from one household to another.

ask turtle 0 [
  create-links-with other turtles in-radius 4
]

show count links

The selected turtle creates undirected links to other turtles within distance 4. The word other excludes the calling turtle itself. The final command reports how many links exist in the model.

4. Putting the pieces together

This complete example creates a two-colour spatial environment, places eight turtles randomly and connects nearby turtles. Press setup once, then press go repeatedly.

to setup
  clear-all

  ask patches [
    if pxcor > 0 [ set pcolor green ]
    if pxcor <= 0 [ set pcolor brown ]
  ]

  create-turtles 8 [
    setxy random-xcor random-ycor
    set color blue
    set size 1.3
  ]

  ask turtles [
    create-links-with other turtles in-radius 4
  ]

  reset-ticks
end

to go
  ask turtles [
    right random 360
    forward 0.5
  ]
  tick
end
Important: this is a teaching model, not a calibrated social-network model. A link is created from spatial proximity only. In real research, the meaning and evidence for a relationship must be defined separately; geographical closeness does not automatically imply social influence.

5. Try these experiments

  1. Change the number of turtles from 8 to 20. What happens to the number of links?
  2. Change the connection distance from 4 to 2, then 6. How does the network change?
  3. Colour the patches differently and explain what the two areas could represent in a real model.
Run the code in the NetLogo desktop application. Add two interface buttons: setup (once) and go (forever, if you want continuous movement). This webpage explains the code but does not execute NetLogo.

Applied modelling cases

These are teaching sketches to help connect ABM concepts to sustainability questions. They are not calibrated or validated research models.

Behaviour

Diffusion of sorting behaviour

Households are represented as agents. Their probability of adopting sorting may depend on exposure to neighbours who already sort. Explore how local influence and initial adoption shape collective outcomes.

Infrastructure

Access to biowaste collection

Households are placed in space and collection points are located on a grid. The exercise asks how distance to a collection point may affect sorting decisions. Real applications should consider road networks, capacity and service quality.

Prevention

Household food waste prevention

A planned case on household routines, food management practices, learning and the conditions that support waste prevention. The full lesson is under development.
